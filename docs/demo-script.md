# SettleSense Five-Minute Demo Script

## Demo Story

A merchant has received money in its bank account but cannot explain which orders and settlement records produced the credit. SettleSense reconciles the sources and highlights what still needs human attention.

## Demo Sequence

### 0:00–0:40 — Problem

Show the Run Setup screen and state that finance teams lose time comparing settlement reports, bank statements, and internal ledgers. Explain that a high match rate is not enough; every match must be supported by evidence.

### 0:40–1:20 — Product and architecture

Introduce SettleSense. Show the three sources entering ingestion, normalization, deterministic matching, exception intelligence, human review, and report generation. Explain that AI provides evidence-grounded explanations while deterministic code controls amounts and matches.

### 1:20–2:20 — Run reconciliation

Select the seeded fixture and start a run containing more than 100 records. Show processing status, source counts, match rate, precision, recall, throughput, matched amount, and unresolved amount.

### 2:20–3:00 — Exact match

Open an exact match. Show matching payment or order ID, amount, date, confidence, source rows, and audit event. Explain why the record was auto-matched.

### 3:00–3:40 — Financial exception

Open a fee, tax, refund, or timing exception. Show gross amount, fee, tax, refund, bank credit, expected net amount, difference, and source-linked explanation. State that the fee or tax behavior is a configurable demo assumption where applicable.

### 3:40–4:20 — Graceful failure

Open an ambiguous record with two plausible bank candidates. Show that SettleSense displays both candidates, explains insufficient confidence, and refuses to force-match the record. Place it in the review queue.

### 4:20–4:45 — Human review

Approve or reject the selected candidate with a reviewer note. Show the new status and the new audit event without deleting the original automated decision.

### 4:45–5:00 — Close report

Export the report. Show metrics, assumptions, matched records, unresolved exceptions, reviewer actions, source checksums, audit references, and report hash. End with the statement: “SettleSense does not pretend uncertainty is success.”

## Demo Data Requirements

Use a committed seeded fixture. Do not depend on live credentials or a network connection for the main demo. If Razorpay Test Mode data is shown, label it explicitly and keep synthetic bank and internal-ledger data clearly separated.

## Backup Plan

If the hosted application or external adapter fails, run the synthetic fixture locally or show a recorded report generated by the same evaluation command. Never hide the failure; the backup must still demonstrate the product workflow.

## Talking Points

- Matching is deterministic and evidence-based.
- AI explains exceptions but cannot invent or change financial values.
- Ambiguity creates human review instead of a forced match.
- Metrics are computed on an independent labelled batch.
- Test Mode and synthetic data are disclosed.
- The close report is traceable back to source rows and audit events.
