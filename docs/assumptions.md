# SettleSense Assumptions

## Purpose

This file contains configurable assumptions for the demo. These values must not be presented as universal Razorpay, banking, accounting, tax, or legal rules.

## Default Assumptions

| Assumption | Default value | Configurable | Notes |
|---|---:|---|---|
| Currency | INR | Yes | Use integer paise or safe decimal arithmetic. |
| Date format | ISO-8601 | No | Store timezone-aware timestamps. |
| Settlement date tolerance | 2 calendar days | Yes | Demo timing assumption. |
| Amount tolerance | ₹1.00 | Yes | Rounding and formatting tolerance. |
| Auto-match confidence threshold | 0.90 | Yes | Only conflict-free records qualify. |
| Human-review confidence range | 0.60–0.89 | Yes | Candidates must be shown. |
| Unresolved confidence threshold | Below 0.60 | Yes | Do not force-match. |
| Dataset size | 100–200 settlement rows | Yes | Buildathon batch requirement. |
| Ground truth | Independent fixture file | No | Must not be generated by the matcher. |
| Fee calculation | Source value preferred | Yes | Demo formula only when source value is absent. |
| Tax calculation | Configured demo rule | Yes | Not tax advice or tax filing. |
| Settlement-cycle treatment | Configured date window | Yes | Account/product behavior may differ. |

## Fee and Tax Assumptions

If a source report contains fee and tax fields, use those source values. If source values are absent in synthetic fixtures, use a versioned demo configuration and show the assumptions in the report. Never infer a universal fee, GST, TDS, or MDR rule from one fixture.

## Synthetic-Data Assumptions

All committed demo records are synthetic. Identifiers, names, account details, narrations, UTRs, and amounts are generated for testing. The dataset is not evidence of Indian merchant behavior or actual Razorpay settlement performance.

## Matching Assumptions

Matching must be deterministic and evidence-based. A record with a conflicting identifier and amount must not be auto-matched. A record with multiple plausible candidates must enter human review or remain unresolved.

## Razorpay Test Mode Assumptions

When Razorpay Test Mode is used, the adapter must preserve the external identifier and raw response. When Test Mode data is unavailable, synthetic fixtures must be used. The application must work without credentials.
